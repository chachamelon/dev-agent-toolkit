# 테스트케이스 합성 및 포맷 표준

## 1. 요구사항 역공학 (Requirements Reverse Engineering) 매핑 가이드

| 분석 대상 | 추출된 시맨틱 요구사항 | 생성된 테스트 시나리오 예시 |
| :---- | :---- | :---- |
| **폼 입력 필드** | 데이터 유효성 검사 및 필수값 제약 | 유효하지 않은 형식 입력 시 에러 메시지 노출 확인 |
| **버튼 활성화 상태** | 조건부 상호작용 로직 | 모든 필수 필드 입력 전 제출 버튼 비활성화 상태 검증 |
| **내비게이션 흐름** | 페이지 간 전이 및 도달 가능성 | 성공적인 제출 후 지정된 완료 페이지로 이동 확인 |
| **접근성(ARIA) 속성** | 스크린 리더 및 키보드 지원 요구사항 | 탭 키 이동 시 포커스 순서가 논리적인지 검증 |

## 2. 거킨(Gherkin) 작성 표준
- **Feature**: 테스트할 기능의 명칭 (예: 로그인)
- **Scenario**: 구체적인 테스트 케이스 명칭
- **Given**: 테스트의 전제 조건 (상태)
- **When**: 사용자의 행동 (이벤트)
- **Then**: 기대되는 결과 (상태 변화)
